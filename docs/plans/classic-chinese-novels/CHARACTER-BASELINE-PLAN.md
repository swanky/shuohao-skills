# 中國古典小說主要角色品質基準規劃

> 執行方式：每部小說先依 [`FEMALE-CHARACTER-BASELINE-PLAN.md`](FEMALE-CHARACTER-BASELINE-PLAN.md) 完成主要女性角色，再完成本文件的互補主要角色，最後去重合併成同一份報告。不分別提交兩份最終報告。《金瓶梅》另依 [`JINPINGMEI-CROSS-REPO-PLAN.md`](JINPINGMEI-CROSS-REPO-PLAN.md) 鎖定外部 repo 的十九人視覺權威。

## 目標

替本目錄中的五部小說建立可版本化的 `novel-characters` 綜合主要角色品質基準：

正式產物根目錄為 `testdata/benchmarks/novel-characters/classic-chinese-novels/`，其下預定包含：

- `紅樓夢-主要角色/`
- `三國演義-主要角色/`
- `水滸傳-主要角色/`
- `西遊記-主要角色/`
- `金瓶梅-主要角色/`

《紅樓夢》《三國演義》《水滸傳》《西遊記》分成兩個八人批次：八位主要女性角色，以及八位不與女性批次重複的互補主要角色。《金瓶梅》依既有外部視覺權威分成十一位女性與八位男性。每部兩批全部完成後才合成單一 JSON、Markdown 與 HTML 報告，既保留女性群像的策展完整性，也避免使用者需要在兩份報告之間切換。

現有的 `testdata/benchmarks/novel-characters/classic-chinese-novels/紅樓夢-主要女性角色/` 是第一批已完成的基礎。製作《紅樓夢》綜合報告時，規劃將該目錄以版本控制保留歷史的方式改名為 `紅樓夢-主要角色/`，沿用八位既有角色卡與預設圖片，再加入本文件規劃的八位角色；不另外複製一套約二十 MB 的相同圖片。

## 共用產出規格

每部小說兩批角色完成後，應只有一套正式產物；《金瓶梅》另附跨 repo 視覺來源映射：

```text
testdata/benchmarks/novel-characters/classic-chinese-novels/<書名>-主要角色/
├── <書名>-主要角色-cast.json
├── <書名>-主要角色-cast.md
├── report.html
├── visual-authority-map.json（僅《金瓶梅》）
└── images/
    └── <角色安全檔名>-sheet.png（每位不重複角色一張）
```

共用設定如下：

- 報告語言：`zh-TW`，人類可讀欄位使用台灣正體中文與台灣慣用詞。
- 生圖風格：`photoreal`，定位為歷史劇或神怪劇的擬真實拍試裝定妝照。
- 最終角色數：前四部各十六位，由八位主要女性角色與八位互補主要角色組成；《金瓶梅》十九位，由十一位女性與八位男性組成。選中的角色全數建立角色卡與設定圖。
- 原文證據：`persona.evidence` 必須逐字保留來源文字；原文中的簡體字、異體字及原標點不得自行正規化。
- 機器提示詞：`image.prompt`、`image.negativePrompt`、`image.tags`、`image.sheet` 與 `voice.prompt` 維持英文。
- 角色區別：同一部作品兩批的所有角色要在年齡、輪廓、服裝、配色、身分、姿態與聲線上可明確區分。
- 額外畫風對照圖不列入新製作範圍；《紅樓夢》既有的林黛玉畫風對照圖繼續保留。

## 執行方式

五部長篇都超過 `novel-characters` 單次 24 分塊的掃描上限，不能把一次 `chunk` 產生的截斷結果直接當成全書角色排名。每部作品依下列流程處理：

1. 按章回切成不會觸發 `truncated: true` 的掃描段；建議《紅樓夢》與《三國演義》每 30 回一段、《水滸傳》每 20 回左右一段、《西遊記》與《金瓶梅》每 25 回一段。
2. 每個掃描段分別執行第一趟角色掃描，保存角色別名、事件摘要與逐字引文。
3. 將各段 roster 依角色名與別名做全書層級歸併，避免別名拆成多人，也避免只取小說前段的角色。
4. 先依女性角色規劃完成女性批次，再以本文件名單完成不重複的互補主要角色批次；兩批都以全書掃描結果確認證據，不單純依出現次數決定。《金瓶梅》另先鎖定外部十九人 authority snapshot。
5. 以角色本名及別名做跨批次去重。若發現重複，保留證據較完整的卡片並由對應候補補足另一批，不得在最終報告出現兩張同一人物。
6. 將前四部各十六張、《金瓶梅》十九張角色卡合成各書單一 `<書名>-主要角色-cast.json`，重寫能涵蓋完整群像的故事摘要，並依敘事重要性與閱讀關係安排角色順序。
7. 使用完整原著執行 `validate`；所有錯誤修正完成並再次通過後才可生圖。
8. 每位不重複角色各自以 `image.sheet` 產生一張設定圖；已通過人工檢查的既有圖片可以沿用，單張失敗不能拿其他角色圖片代替。
9. 該書全部圖片完成後，才由合併後的 JSON 產生唯一一份 Markdown 與 HTML 報告。
10. 完成自動校驗與人工檢查後，才將最終基準產物提交版本控制；分批 JSON、分塊、roster 與單卡等中間工作目錄不提交。

## 建議執行順序

1. 《紅樓夢》：沿用已完成的女性八人，先補八位互補主要角色並驗證合併報告流程。
2. 《金瓶梅》：以外部十九人 current authority 驗證跨 repo 格式轉換、身份鎖定與 provenance 流程。
3. 《三國演義》：驗證大量本名、字、官職與稱號的別名歸併。
4. 《水滸傳》：處理更大的群像與綽號系統，並確認七十回版本邊界。
5. 《西遊記》：最後集中處理人、神、妖混合的外貌設計與非人型角色一致性。

每完成一部就獨立校驗、人工檢查並定稿，不必等五部全部生圖完才檢查第一部。

## 驗收條件

每部小說必須同時符合下列條件才算完成：

- 前四部的 `cast.json` 各有十六位不重複角色，包含八位主要女性角色與八位互補主要角色；《金瓶梅》有十九位，包含十一位女性與八位男性。名稱與別名均沒有重複拆分。
- 對完整原著執行 `validate`，結果零錯誤。
- 每位角色都有足量且確實來自原文的證據，重要判斷若非原文明示須標示為推斷。
- 該書每位角色的預設設定圖全部存在，角色臉部、三視圖身分與服裝一致，身體比例合理；非人型角色使用適合其身體結構的等價檢查。《金瓶梅》另需十九筆完整的視覺來源 hash 映射與跨 repo 並排檢查。
- 服裝、兵器、冠帽及宗教元素符合故事時代與作品語境，避免現代服裝、廉價 cosplay 質感或混用不相干朝代符號。
- 不同角色不共用近似臉型、髮型、主色與聲線；跨陣營、階級或物種的差異清楚。
- `cast.md` 與 `report.html` 可正常開啟，圖片路徑正確，介面文案為台灣正體中文。
- 人工抽查每位角色至少一條引文、主要關係、外貌提示詞與聲音提示詞。

## 本輪完成定義

完整計畫最終應有五個綜合品質基準目錄、八十三份不重複角色卡、八十三張預設角色設定圖，以及五份 Markdown 與五份 HTML 報告。扣除《紅樓夢》已完成的八位女性角色，本 repo 尚需新增七十五份角色卡與七十五張設定圖；其中《金瓶梅》十九張設定圖必須由外部 current authority 轉換，不是自由重設人物。規劃文件完成不代表角色產物已開始製作；實際執行時以「一部小說兩批角色完成、合併並驗收」為最小交付單位。
