# 站位報告的設計約定

報告由 `scripts/novel-staging.mjs render --html` 生成，樣式和頁面腳本全部內聯在 `renderHtml()` 裡。**改樣式只改那一處。**

跟其餘幾份報告同一套視覺語言：冷灰印張 + 鐵鏽紅印記，1600 寬，零外部依賴，離線雙擊能開。跟它們不一樣的是**這份報告能調整**：每一場一張俯視平面，人可以拖動，改完匯出就是新的 staging.json。

## 結構

```
頁首      劇名 · 開場站位 · 改動狀態 · 品質門徽章 ·（有改動才出現）還原 · 匯出 JSON
KPI 帶    場次（幾場有人開場不在）/ 地點（幾個按圖認的）/ 開場在場人次 / 群演
（病灶橫幅）品質門有未過項才出現
01 各場開場站位   每場一張大卡（報告的主體）
02 地點與認出來的東西   每個地點一張卡：場景圖 + 東西清單
03 品質門     render 那一刻的 ✓/✗ 清單
```

## 每場一張卡

左邊是**俯視平面**（16:10，上北下南、左西右東，方位字在平面外面一圈），右邊從上到下：這個地點的場景圖（小圖）→ 選中的人 → 群演 → 開場走位句（帶複製按鈕）→ 為什麼這麼排 → 這一場的實時檢查。

- **東西**按 `plan` 畫成框，能坐能站的框是鐵鏽色；圓的畫成圓。名字貼在框的左上角、不折行：人站在東西中間時不擋名字。
- **人**是圓點，點上寫名字的第一個字，下面寫全名；坐著的顏色淺一點；一個小三角指著他面朝的方向。點的位置由「東西 + 哪一側 + 沿著多遠」算出來（`placePoints`），跟走位句永遠是一回事。
- **拖動**：按住一個人拖到平面上別處，鬆手時落在最近那件東西最近的一側（`nearestPlace`）；松在能坐的東西里面就坐在它上面。拖的時候目標那件東西亮起來，右邊場景圖上同一件東西的框也亮。換了東西或換了一側，人自動轉過去面朝它；從托盤拖進來的人站著，落在能坐的東西上就坐下（`moveTo`）。
- **托盤**在平面下面：開場不在場的人。拖進平面就是在場，拖回托盤就是開場不在。
- **點一下**一個人：右邊出現坐著／站著、朝向（八個方位的羅盤）、移出。
- **群演**：加減按鈕 + 「在哪」一行字；人數變成 0 時「在哪」自動清空。
- **實時檢查**：每改一次，這一場按跟 `validate` 同一份規則（`sceneProblems`）重算，有問題用鐵鏽紅列出來。

頁面上的演算法跟命令列是同一份：`stagingCore()` 整個用 `toString()` 嵌進頁面。所以 `stagingCore` 的函式體裡不許引用外面的任何東西，自測會單獨拿它的原始碼重建一份來核對。

## 改動、儲存、匯出

- 每次改動存進這臺電腦的瀏覽器（`localStorage`，按檔案內容區分），重新整理不丟；檔案重新 render 過、內容變了，就不再套用舊的改動。隱私模式下存不了，照樣能改能匯出。
- 頁首顯示「頁面上改過，還沒匯出」，匯出按鈕變成鐵鏽紅實底。
- **匯出 JSON** 下載的是改過的 staging.json，餵回 `validate` / `render` / `blocking` 照樣能用。兩個坑照舊：嵌入的資料裡 `<` 轉義防 `</script` 截斷；`revokeObjectURL` 延後調防 Safari 存出空檔案。
- **還原到檔案裡的版本** 要點兩次（第一次變成「再點一次還原」，三秒內再點才還原），防手滑；不使用瀏覽器的確認彈窗。

## 地點卡

一排兩張。場景圖（有圖才有）上按 `box` 畫出認出來的每件東西，滑鼠移到清單的某一行或平面上的某件東西，圖上對應的框亮起並標出名字。沒有圖時是佔位，寫明圖應該放在 `images/<地點名>-sheet.png`。`readFrom` 是 `prompt` 的地點標「沒有圖，按設定提示詞推算」。

## 品質底線

- 模型生成的資料一律 `esc()` 轉義
- 中文文案不用單字詞（坐著／站著、正北／正東，不寫單字）
- `@media print`：隱藏按鈕、托盤和選中面板
- `prefers-reduced-motion` 關動效
