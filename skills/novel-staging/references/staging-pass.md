# 排站位：一場戲開場時誰在哪

給每一場排開場站位：這一場一開始，每個出場的人在這個地點的哪件東西旁、坐還是站、面朝哪。分鏡這一場第一段的開場走位就照抄它，之後各段的走位從這一句接著往下寫——它定下來以後，同一場裡誰坐在哪就不會每段變一次。

為什麼要先排：短劇的每一段影片是一次獨立生成，各段自己決定誰坐哪。群戲裡六個人圍一張長桌，第一段桌邊多出五個沒名字的賓客，第三段端酒坐著的人穿著主角的衣服——走位句一字不差地交接也沒用，因為每一場第一段的那一句是分鏡自己編的。

每場拿到：這一場的劇本（場次的 `flow`）、出場人物（`cast`）、這個地點認出來的東西（`locations[].items`）。

## 規則

1. **先讀這一場的劇本，分清誰開場就在、誰是後來才進來的。** 後來才進來的人開場不在（`present: false`）。劇本沒寫某人進場，就當他開場就在。
2. **坐還是站跟著劇本走**：一開場大家在吃飯、開會、喝茶、乘船，就坐著；站著的人要有理由——剛進門、在伺候、在撐船、被罰站、正要發難。不要為了畫面好看讓坐著的戲站起來。
3. **按身份和關係排位置**，讓觀眾一眼看懂權力關係：
   - 長輩、掌權的人坐主位（正對入口、地勢最高或最中間的那個位置）。
   - 對立的兩方隔著桌子相對，或者一坐一站；主角和站在他那邊的人在同一側。
   - 被孤立、被看不起的人坐在最末的位置（離主位最遠、靠門的一端），或者乾脆站著。
4. **給鏡頭留路**：這場戲裡對話最多的兩個人之間不要隔著第三個人；不要把所有重要的人都排在同一側背對入口。
5. **朝向**：坐著的人一般面朝桌子（東側的人面朝西）；坐主位的人面朝全場；站著的人面朝他開場時在看、在說話的那個人或方向。
6. **群演**：劇本沒寫還有別人，就是沒有別人，其餘座位空著（`extras: 0`）——不要為了「熱鬧」加人，影片模型會把多出來的位置畫成一個個有臉的人。劇本寫了滿座賓客、旁觀的人群，才給群演人數和他們在哪。
7. **只使用認出來的那些東西站位**——認圖結果裡沒有的傢俱不要發明，劇本里提到、圖上沒有的也不要使用。同一側的幾個人沿這一側排開（`along` 至少拉開 0.12），不疊在同一個點上。只有 `on: true` 的東西才能寫 `on`。圍著桌子坐的人落在桌子那一件的哪一側（「坐在長餐桌東側」），不要落在「椅子」上。
8. **前後幾場連著在同一個地點**（一路坐船、一頓飯分幾場）：沒有劇情讓人換位置，就照上一場的位置排，只改朝向和坐站。觀眾記得誰坐在哪。
9. **寫一句 `why`**：為什麼這麼排（誰開場不在、誰坐主位、為什麼站著）。報告裡顯示給人看，人改的時候知道原來的考慮。

## 按一句話調整

有人說「把胡二爺挪到船頭」「蕭老太太改成站著」時，是在**現在的站位上按要求改**，不是重新排：要求說到的人和東西才動，其餘每個人的 `item`、`side`、`along`、`posture`、`facing` 和群演一律照抄現在的。要求是人定的，跟劇本或上面幾條衝突時按要求來；要求裡說的東西認圖結果裡沒有，就落在最接近的那件上，並在 `why` 裡說一句。改完照樣跑 `validate`。

更快的做法是直接在報告頁面上拖：見 SKILL.md 的 Step 5。

## 寫法

```json
{
  "ep": 1, "scene": 2, "sceneId": "S01",
  "cast": [{"id":"C01","name":"沈知微"}, {"id":"C04","name":"胡二爺"}],
  "places": [
    {"id":"C01","name":"沈知微","present":false,"item":null,"side":null,"along":null,"posture":null,"facing":null},
    {"id":"C04","name":"胡二爺","present":true,"item":"第三排坐板","side":"on","along":0.5,"posture":"sit","facing":"north"}
  ],
  "extras": 0,
  "extrasWhere": null,
  "why": "沈知微隨後進艙，開場不在；胡二爺帶著貨擔坐第三排。"
}
```

`cast` 是 `seed` 搬來的，不改；`places` 裡每個出場人物正好一條。欄位的完整說明見 `schema.md`。
