# 場景設定 · 怎麼填

給你一個場景的骨架（seed 預填了 id/名稱/主場景標記/出現集/承載爽點）+ 原文或大綱裡關於這個空間的全部資訊，產出完整的場景設定。**只輸出 JSON，不要解釋、不要圍欄。**結構見 `schema.md`。

## 先想清楚：這是 AI 短劇，不是實拍

場景不是「尋找實拍場地」，而是**會被生成數十次、每次都必須維持一致的環境資產**。每個欄位都在為一致性服務：

| 欄位 | 它在解決什麼 |
| --- | --- |
| 錨點 | 觀眾靠什麼認出「又回到這裡了」；QC 靠什麼判斷生成的鏡頭沒漂 |
| 光照狀態 | 換時段 = 換提示詞重新生成，不是現場重新打光 |
| 空景 | 人是另一層資產（novel-characters 管），環境參考圖裡有人，一致性全毀 |

## 硬規則

1. **`summary` 寫設計意圖，不寫空間格局說明。**「小到人與人躲不開視線的審訊室」是設計意圖；「約十平方公尺，六排坐板」只是測量資料。空間要為戲服務，先說它為哪場戲存在。

2. **錨點要「可畫、可辨識、可核對」。**好錨點：補丁船篷、斷裂的第七塊橋板、綠鏽銅鈴——生成圖裡一眼找得到，缺少時能立刻發現。壞錨點：「陳舊的氛圍」「歲月的痕跡」——無法核對的不是錨點，只是形容詞。每個錨點的 `name` 應簡短到能放進核對表，`desc` 則要寫清位置和特徵。

3. **光照狀態從分集反推。**依場景出現集數中的時段與天氣填寫狀態，不要憑空列出「白天／夜晚／黃昏」的完整組合——不會使用的狀態只會增加維護負擔。

4. **提示詞永遠英文，永遠空景。**`image.prompt` 裡明寫 empty scene / no people，`negativePrompt` 必須禁人。**絕不出現角色名、作者名、作品名**——圖像模型會把它認識的東西畫進去。

5. **風格整套取用。**執行 `node scripts/novel-art.mjs styles` 取得目前風格的 render／surface／negative／tags，`image.sheet` 必須完整包含渲染句和表面處理句，不要混搭兩種風格。

6. **能做變體就不要另開新場景。**AI 生成一個新環境很便宜，但**每多一個獨立環境，就多一份一致性維護工作**。outline 裡帶複用方案的場景（seedNote 會提示），應以 `variantOf` + `changes` 掛到母場景下：改時段、換天氣、換前景、刪道具，橋板細節這類資產則直接複用。

7. **不要把角色 skill 的表面處理帶進來。**毛孔、皮下散射是皮膚的事；環境的真實感來自**用舊的材質**——掉漆、水漬、包漿、磨白的木紋。預設裡寫好了，照用。

## 輸入格式

```
Style: realistic
Scene: S01 渡船船艙（主場景）
出現集：1–6　承載爽點：懸念鉤、身份揭破、反轉、收束

原文/大綱裡關於這個空間的資訊：
- ……
- ……

同批其他場景：S02 渡口棧橋、S03 對岸蘆葦灘
```

同批其他場景要彼此知道名稱——空間氣質必須能區分，不要把每個場景都寫成同一種「破舊」。
